## Overview

You can add a cloud provider account to Cloud 66 in one of two ways:

1. During initial app set up (Click the *New Application* button to get started)
2. Via **Account Settings**

To add a cloud account via Account Settings:

1. Click on your avatar (top right) and select *Account Settings*
2. Click on Cloud Platforms in the Settings panel (on the left)
3. Click the *+ Add Cloud* button
4. Add the cloud account details to the drawer that opens from the left 
5. Click *Add Cloud*

Follow the instructions for your preferred cloud provider below to grant Cloud 66 access to your account.

## Removing Cloud 66's access

You can remove Cloud 66's access to your cloud account at any time, in two places.

**In Cloud 66:** go to *Account Settings → Clouds & Integrations* and delete the cloud account. You can't delete it while applications, clusters or image registries still use it, so remove those first.

**In your cloud provider:** delete or revoke the credential you gave Cloud 66. This removes access immediately, even if the cloud account is still listed in Cloud 66.

| Provider | How to revoke the credential |
| --- | --- |
| AWS | In IAM, deactivate and delete the access key, or delete the `cloud66` IAM user |
| Azure | In the Azure portal, open your app registration and delete its client secret under *Certificates & secrets* |
| DigitalOcean | Go to *API → Tokens* and delete the token |
| Google Cloud | In *IAM & Admin → Service accounts*, delete the service account's key, or delete the service account |
| Hetzner Cloud | In your project, go to *Security → API tokens* and delete the token |
| Linode | Go to *My Profile → API Tokens* and revoke the token |
| OVHcloud | Revoke the API access you granted Cloud 66 when you connected your project |
| Vultr | Go to *Account → API* and regenerate the API key, or disable API access |

<Callout type="warning" title="Removing access doesn't delete your servers">
Servers that Cloud 66 created keep running in your cloud account, and your provider keeps billing you for them. If you're stopping using Cloud 66, delete your applications and clusters in Cloud 66 first so it can remove their servers, then revoke the credential. Otherwise, delete the servers yourself in your cloud provider's console.
</Callout>
